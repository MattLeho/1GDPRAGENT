# Task 6 Privacy Capability Architecture

PostgreSQL is authoritative. Neo4j is a profile-scoped, high-value derived projection. Model output may select a typed read tool and explain its cited result; it cannot promote capability, legal, access, deletion, or hypothesis status.

## Capability and linkability

The versioned taxonomy contains fourteen capabilities. Deterministic rules emit `CapabilityCandidate` records before explanation and preserve the six exposure states: evidenced from export, documented, legally authorised, technically possible, speculative, and human confirmed.

Structural linkability is an evidence vector plus exact graph metrics, not a universal privacy score. Snapshot hashing covers all calculation inputs. Brandes betweenness, Tarjan articulation points, occurrence/persistence/context counts, and identifier graph-cut simulation are reproducible against the named snapshot.

## Purpose, policy, and access

Policy acquisition stores canonical authorised UTF-8 bytes, SourceArtifact versions, and exact locators. Task-Router claim candidates are persisted only when their exact quote resolves. Purpose, LegalBasis, Claim, ProcessingActivity, current scope, original justification, and technical reach remain distinct. Distance output is always labelled “Possible purpose drift” and is not a legal conclusion.

Datasets, custody, storage topology, identifier overlap, technical linkability, institutional access, sharing, and legal gateways are distinct. Every access edge needs an Assertion; a legal gateway additionally needs its legal instrument and requirements. Identifier overlap alone cannot create access.

## Hypotheses and deletion

Deterministic evidence gaps create `PrivacyHypothesis` uncertainty objects and targeted questions. Drafting reuses the existing request workflow. Only new assertion evidence can confirm or reject a hypothesis; every state transition is audited.

Deletion analysis predicts expected removals from a named graph snapshot and plan. A later absence can establish only `CONFIRMED_REMOVED_FROM_OBSERVED_EXPORT`. It never establishes legal deletion or deletion from every controller system.

## Typed query and UI

`PrivacyQueryService` exposes exactly the nineteen Task 6 tools. Arguments are closed Pydantic contracts, reads are profile-scoped, and evidence-bearing results cannot validate without Assertion/EvidenceLocator/SourceArtifact citations. Audit rows hash every result. The legacy natural-language Python query endpoint and keyword/Cypher graph chat are retired from the Task 6 surface.

The graph API accepts `asOf`, `compareTo`, `profileLayer`, `epistemicBasis`, `assertionStatus`, `capabilityStatus`, `purpose`, `sourceArtifact`, `controller`, and `dataDomain`. The UI supplies eight modes, four explicit profile layers, temporal comparison, three drift views, cited typed queries, and an inspector with epistemic, temporal, derivation, assertion, artifact, and locator fields.
